# Shared external-routing reference

Read this only before using an external CLI route. Keep calls short, fresh, self-contained, and scoped to one independently verifiable leg.

## Capability registry

**This table is the only place model IDs, invocation shapes, and effort ladders are stated.** Provider references carry judgment, prompt discipline, and failure forensics — not command shapes. When a CLI changes, edit here and nowhere else. Each invocation shape also states its pre-authorized prefix, the owner-approved permission posture: `sync.sh` and `sync.ps1` refuse to install unless the Claude adapter's `allowed-tools` lists exactly those prefixes (plus the `command -v` / `Get-Command` probe) as Bash entries with PowerShell twins, and each prefix starts its own command. Widening a prefix is an owner decision made here, not in the adapter.

| Route | Command | Pre-authorized prefix (allowed-tools) |
|---|---|---|

| Codex — write leg | `codex exec -s workspace-write -m <model-id> -c model_reasoning_effort="<effort>" -o <outfile> "<prompt>"` | `codex exec -s workspace-write` |
| Codex — web research (read-only) | `codex --search exec -s read-only -m <model-id> -c model_reasoning_effort="<effort>" -o <outfile> "<prompt>"` | `codex --search exec -s read-only` |
| Grok — headless | `grok --always-approve --no-subagents --no-alt-screen --minimal --output-format json -m <model-id> --reasoning-effort <effort> --prompt-file <path>` | `grok --always-approve` |

| Claude — code review (Codex/Grok hosts) | `claude -p --safe-mode --model <model-id> --effort <effort> --tools "Read,Glob,Grep" --allowedTools "Read,Glob,Grep" --permission-prompts none --system-prompt "<reviewer persona>" --output-format json --no-session-persistence "<review packet>"` | `claude -p` |

Per-route qualifiers:

- **Codex** — `-m` takes the registry default or an explicitly requested available model ID. Run from the intended Git worktree; do not bypass the repository check by default. Use `--skip-git-repo-check` only for an intentionally trusted non-Git directory after checking the environment. The sandbox is a per-leg decision: read-only for research and review, `workspace-write` only when edits are needed. The final message appears on stdout and is also copied to the `-o` file; progress goes to stderr. For a multiline prompt, pass a file as stdin with `codex exec ... - < prompt.txt`. For measured reviews, add `--json` and retain events outside the reviewed snapshot; verify the startup model/effort and use reported usage, never model self-identification alone. The `--json` events carry no model field (codex-cli 0.162.1, 2026-10-11): take `thread_id` from the `thread.started` event and read model, effort, and sandbox policy from `~/.codex/sessions/YYYY/MM/DD/rollout-*-<thread_id>.jsonl`.
- **Codex web research** — verified on codex-cli 0.162.1, 2026-10-11. `--search` is a root-level flag and goes before `exec`; it enables the native Responses `web_search` tool with no per-call approval. Always read-only, from a throwaway Git directory. Sol `high` for citation-bearing research, `medium` for narrower sweeps; for Luna, `low` truncated a 12-prompt multi-query run to one answer, so use `medium` and one query at a time. The search index can trail the newest releases by days, so primary-fetch any version or date claim. Strip raw citation markers (`cite…`) from the `-o` output before reuse.
- **Claude code review** — verified CLI options in 2.1.286 on 2026-10-01; this is separate from the no-tools Advisor route. Prefer a fresh native Claude reviewer on a Claude host; otherwise use this CLI recipe from the frozen review checkout. Safe mode disables customizations, so include relevant repository instructions in the review packet. The only exposed tools read/search files; shell, writes, and agent spawning are unavailable. The reviewer persona and packet are defined in `claude-delegation.md`. Multiline packets may be piped on stdin with no positional prompt. Check exit status, `is_error`, non-empty substantive `result`, and actual served IDs in `modelUsage`; a fallback or unavailable model cannot be credited as the requested candidate. The orchestrator runs any needed repro commands and supplies the same evidence to all candidates. Do not widen tools or bypass permissions to repair a failed review.
- **Grok** — pin `-m` to the registry ID; do not rely on the CLI default. Add `--disable-web-search` for code/engineering legs; omit it for live-X research. Read-only legs are contained by an explicit read-only prompt contract rather than a sandbox flag (see Permissions). `--permission-mode plan` is interactive-only. Never pass `--json-schema` on agentic legs. Run synchronously from a throwaway worktree. Effort spelling: CLI validates `--reasoning-effort` and hard-fails bad values with exit 1 listing `xhigh, high, medium, low` (verified 2026-08-15); the raw API instead silently downgrades unrecognized strings to `high` (practitioner-verified 2026-08-12) — that trap applies to non-CLI harnesses only. 4.7's API-side default is `high` and reasoning cannot be disabled. Context window is 500,000 tokens (re-pricing threshold cliff at 200,000 prompt tokens doubles pricing on all tokens). **Research tools depend on the model entry's backend; smoke-test before each research leg.** X search (`x_keyword_search`/`x_semantic_search`) is a server-side xAI tool that exists only on the **Responses API**.
  - **Works (CLI 1.0.41, 2026-09-27):** a `[model.*]` entry with `api_backend = "responses"` and `supports_backend_search = true`.
  - **No X search:** a `chat_completions` entry, which gets `web_search` only. Also a free-tier grok.com login (`subscription_tier: Free`), which got `web_fetch` only although the handshake advertised the X tools.
  - `web_fetch` is off by default; enable it with the documented `features.web_fetch = true` config key.
  - **Relay-routed Grok is retired (owner decision, 2026-10-16).** Every Grok leg, research or engineering, pins the registry ID `grok-4.7` (or `grok-4.6` for bake-offs) on the xAI-native login. Never pin a `[model.*]` entry with a custom `base_url`, even when it is the device's `[models] default`. Verified 2026-10-16 through T3: native `grok-4.7` (served as `grok-4.7-build`) called the server-side `x_keyword_search`, and 3/3 returned post IDs resolved. If the native login lacks X search or hits its usage limit, the route is dead for the session: use the fallback, not a relay.
  - X search is billed per post and per profile fetched, on top of tokens.
- **Antigravity** — `--print-timeout` defaults to `0s`, which waits indefinitely (changed from 5m in agy 1.2.6; the official headless guide still says 5m), so always pass a bound: `5m` for Flash and Argon `low`, `20m` for Argon `high` or deep sweeps (Google: Argon has "occasional slowness or timeout issues"). Add `--output-format json` to measured legs; it returns `status`, `response`, `error`, `duration_seconds` and `usage` (`input_tokens`, `output_tokens`, `thinking_tokens`, `cache_read_tokens`); it has no served-model field, so score effort from `thinking_tokens` and treat model identity as unattested. A model/effort conflict returns `status: "ERROR"` with exit 1. Write the prompt to a file and pass `-p "$(cat promptfile)"` rather than a heredoc. In headless runs, unconstrained prompts risk agy attempting shell commands, which are soft-denied to stderr causing empty stdout; always prepend an explicit tool rule (e.g. `TOOL RULE: use ONLY built-in web search and fetch tools; do NOT execute terminal or shell commands`) to prevent tool-denial empty deliverables.
- **Advisor** — the `--system-prompt` body is fixed and non-optional; it lives in `fable-advisor.md` with the dossier discipline and launch-validation rules. Codex hosts must run this call outside the exec sandbox.

Do not guess additional flags. For multiline prompts use a file — stdin with `-` (Codex), stdin (Claude code review), `--prompt-file` (Grok), `-p "$(cat …)"` (agy), `"$(< …)"` (advisor) — rather than brittle shell quoting.

### Host-native subagent routes

On a Claude host these run as subagents rather than CLI calls. The IDs are the same ones the advisor route passes to `--model`. The agent definitions (installed to `~/.claude/agents/` by `sync.sh`/`sync.ps1`) fix model and tools only; effort is chosen per launch through the Agent tool's `effort` parameter, from the ladder below. Without it a subagent inherits the session's effort (verified Claude Code 2.1.296, 2026-10-11: a `high` session gave `high` subagents; a per-launch `medium` logged `medium`).

| Codename | Model ID | Agent definition | Ladder (**default**) | Role and caveats |
|---|---|---|---|---|
| Fable 5.1 | `claude-fable-5-1` | `mr-fable-advisor` | `medium` (clean-read triggers) · **`high`** | Advisor default for frontier architecture, security/trust boundaries, novel migrations; high-stakes review escalation |
| Opus 5.5 | `claude-opus-5-5` | `mr-opus-reviewer` | `low` (user in the loop) · **`medium`** · `high` (security, concurrency, difficult cross-file review, verification) | Pragmatic advisor; running code reviewer always paired with the Codex default, and its fallback; never `max` by default; economical ($4/$20) with high fidelity |

The `sonnet` alias served this ID on 2026-10-11 |

### T3 Code delegated-task routes

Only on a T3 Code host (v0.1.0, orchestration v2). The `t3-code` MCP tool `delegate_task` launches a child thread on another provider. It is not a shell command, so it has no `allowed-tools` prefix; T3 passes `allowedTools: mcp__t3-code__*` to Claude sessions it starts (source). Classifier verdicts go in `t3-code.md` like any other shape. T3 never routes by itself: the target below is the whole routing decision (verified in T3 source, `OrchestratorMcpService.ts` `resolveTarget`). When to prefer this transport over the CLI shapes is judgment in `t3-code.md`.

| Route | `target` | Effort option | Never set |
|---|---|---|---|
| Codex Sol / Luna / Terra | `driverKind: "codex"` or `providerInstanceId: "<device instance ID>"` (`routing-notes.local.md`), `model: <registry Codex ID>` | `options: {reasoningEffort: "<effort>"}` | `serviceTier: "priority"` (fast mode) |
| Grok | `driverKind: "grok"`, `model: "grok-4.7"` | `options: {reasoningEffort: "<effort>"}` | — |
| Antigravity | `driverKind: "antigravity"`, `model: "gemini-3.8-flash-<low\|medium\|high>"` or `"gemini-4-argon-<low\|medium\|high>"` (both in T3's catalog, 2026-10-24) | encoded in the slug | — |
| Claude (only when the native Agent tool cannot serve the model) | `driverKind: "claudeAgent"`, `model: <registry Claude ID>` | `options: {effort: "<effort>"}` | `fastMode: true`, `ultracode` |

Call qualifiers (verified in T3 v0.1.0 source):

- **Always pass effort.** Options carry over only to the parent's exact instance and model. Any other target gets the provider default, which for `gpt-6.1-sol` is `low`. A target with a driver but no model gets that provider's first listed model.
- **`clientRequestId` makes a retry replay instead of relaunch.** Use one stable ID per leg and round (e.g. `<pipeline>-<leg>-r<n>`). Without it every call starts new work. `t3_thread_launch` has no idempotency key.
- **`mode: "async"`** (default) and end the turn: completion arrives as a notification. `wait` blocks up to `timeoutMs` (default 10 min, max 60 min) and a timeout does not cancel the child.
- **`isolation: "worktree"`** checks out the parent's current HEAD commit and runs project setup. Uncommitted edits are not copied, so commit the write checkpoint first. The default `shared` uses the parent checkout.
- **`runtimeMode` is the Codex sandbox.** Unset, it inherits the parent thread's mode (T3's default is `full-access`), and a mode above the parent's is rejected. Codex mapping (`CodexAdapterV2.ts` `codexRuntimeModeTurnDefaults`): `approval-required` → read-only sandbox with approval `untrusted`; `auto-accept-edits` → workspace-write, `on-request`; `auto` → workspace-write, `on-request` with `auto_review`; `full-access` → danger-full-access, approval `never`. Approvals are not routed to the parent, so `approval-required` and `auto-accept-edits` stall a headless child. There is therefore no unattended read-only Codex leg through T3: a review child of an `auto` parent ran `workspace-write`, network off (rollout, 2026-10-16).
- **The result is the child's last assistant message only** (or the provider error). For the timeline, `t3_thread_read` the `childThreadId` with `view: "activity"` and page with `afterPosition` until `hasMore` is false; the default `messages` view omits tool activity. `role` only prefixes "Act as the <role> sub-agent"; the child gets no parent history.
- **No per-child token or cost fields.** T3 aggregates usage only on its Usage page. Codex children still write a rollout under `~/.codex/sessions/` (`originator: "T3 Code"`) with model, effort, sandbox, and token usage; Grok children write `~/.grok/sessions/<cwd>/<id>/usage.json`.
- **Grok effort is not applied through T3 (observed 2026-10-16, cause unknown).** `reasoningEffort: "low"` was requested; every model call in the session's `chat_history.jsonl` logged `reasoning_effort: "high"`, the device's `~/.grok/config.toml` default. Legs whose Grok effort matters, and scored Grok legs, use the CLI shape.
- **Not exposed:** an unattended Codex read-only sandbox (see `runtimeMode`), `--search`, network access, `-o`; Grok `--disable-web-search`; agy `--add-dir` and `--print-timeout`. Legs that need one of these use the CLI shape.

### Unverified gaps

Treat these as open, and never fill them with a guess:

- **Grok identity and backend.** `grok models` lists `grok-4.7` (2026-09-26) as the active default, and also offers `grok-4.6` and legacy `grok-4.5`. Pin `-m` to the registry ID. Before blaming quality on the route, confirm two things:

  A run that returns only `site:x.com` web-search summaries, or whose sampled IDs don't resolve, is a backend problem (see Known route failures), not the model.

- **agy served-model identity.** The print-mode JSON names no served model and Google documents none; `--effort` mismatches fail loudly, but a silent server-side fallback would not show. Compare `thinking_tokens` and latency against the slug's expected profile before scoring a leg.

## Permissions

- Read-only research/review: Codex `-s read-only`; Grok headless `--always-approve` from a throwaway cwd with an explicit read-only prompt contract ("do not create, modify, or delete files; use only search/fetch tools") — headless `--permission-mode plan` auto-cancels the first tool call and kills the run (verified 2026-07-24: `stopReason:"Cancelled"` + narration-only text on a pure research leg, same signature as `auto`); reserve `plan` for interactive sessions. agy plain `-p` (web search/fetch run without prompting; tools needing approval are soft-denied with a stderr notice naming the allow-rule — empty stdout plus such a notice means blocked, not failed; prepend explicit prompt tool rules to prevent unapproved shell tool attempts).
- File edits: Codex `-s workspace-write`; Grok `--always-approve` — never `--permission-mode auto` headless: auto silently auto-CANCELS any non-whitelisted shell command (e.g. heredoc file writes) and ends the whole run with empty output; it is only safe interactively. Deny rules and hooks still apply under `--always-approve`, so containment comes from those plus a throwaway worktree. agy write legs are not an established route. Never use `--dangerously-skip-permissions`. Instead, grant specific allow-rules (e.g. `"read_url(*)"`, `"search_web(*)"`) in `~/.gemini/config/config.json` → `userSettings.globalPermissionGrants.allow`. On agy 1.4.9 (2026-10-28) the live grants merge two stores: `~/.gemini/antigravity-cli/settings.json` → `permissions.allow` (scope `global`, the officially documented location; ignored on 1.1.22) and `~/.gemini/config/config.json` → `userSettings.globalPermissionGrants.allow` (scope `shared`). `agy -p "/permissions" --output-format json` dumps the merged grants; check it rather than assuming either file.
- Grant only the minimum task-scoped access. Do not pass credentials or production secrets to delegated legs.
- Claude code review exposes only the registry's read/search tools in safe mode; permission prompts are denied. Review feedback stays in the task: applying fixes or posting a source-provider review is a separate user request.

## Completion gate

A worker result counts only when it includes relevant artifacts and real verification. Reject empty output, narration-only output, unverifiable completion claims, or changes outside the scope lock.

For Codex **write** legs, also reject **code bloat** as a failed deliverable (not a soft style note):

- Diff must stay within the scope lock; no unexplained new packages or files.
- Net LOC / new symbols grossly disproportionate to the task (e.g. large helper layers for a small fix) → reject once and re-prompt with the minimal-code contract from `codex-delegation.md` plus: "Delete the unnecessary machinery; do not add more."
- Spot-check: any new helper used only once should usually have been inlined.
- Require `git diff --stat` (or equivalent) in evidence when files changed.

For **review** legs, also reject **review bloat / ungrounded nits** as a failed deliverable:

- Findings must be caused by the pinned commit range or frozen local-change snapshot; direct callers/callees may be inspected to establish impact. All candidates must see the same snapshot (see `codex-delegation.md`).
- Reject speculative nits lacking a concrete failure scenario and supporting trace, test, or command when feasible; re-prompt under the `Code-review contract`.
- Require at most five supported P0–P2 findings, ordered by severity, with file:line, trigger, failure path, confidence, evidence, and smallest correction. Use the review result contract in `codex-delegation.md`; P2 findings are not a clean review, and an unavailable/incomplete route must never return approval.

For high-risk work, require a fresh review from another model family where practical. The orchestrator remains responsible for the final decision.

## Known route failures

- A present binary may still have broken auth, quota, account tier, or configuration. The first real call is the probe.
- **Unattended SDK hosts (e.g. T3 Code).** The auto-mode classifier can deny a registry shape that `allowed-tools` lists. A denial is a dead route for the session. Per-shape verdicts live in `references/t3-code.md`.
- The gemini CLI is permanently dead: Google retired it 2026-06-18 in favor of Antigravity (`agy`); `IneligibleTierError` was the shutdown symptom. Do not probe it.
- An unresolvable agy `--model` hard-fails with a non-zero exit listing valid slugs — fix the slug, don't retry. A sweep that dies exactly at its `--print-timeout` bound hit the bound, not a model failure; one that never returns had no bound (the default is `0s`). Headless runs returning empty stdout with stderr "a tool required the command permission" mean agy attempted unapproved shell commands; add explicit prompt tool rules or configure allow-rules in `~/.gemini/config/config.json` (see Permissions). Headless agy also cannot read local files without a `read_file`/`command` allow-rule, so pass bulk text inside the prompt rather than asking it to open files.
- **agy can hang after delivering its result** (1.4.9, 2026-10-28, 2 of 13 sequential legs, both models): the process printed its complete `--output-format json` result and then never exited. `--print-timeout` did not end it, and one process ignored SIGTERM. The next leg in a sequential loop never starts. Use a watchdog that waits for a parseable JSON object with a `status` field in the output file and then ends that one process (`kill -9 <pid>` from `pgrep -x agy` plus its command line, never `pkill -f`). The delivered result is valid.
- Grok background `nohup ... &` invocations fail to retain usable results in subshell tool executions. Run Grok synchronously (registry shape); on Windows the standard prompt-file path is `$env:TEMP\prompt.txt` or `%TEMP%\prompt.txt`.
- In zsh, do not use `status` as a variable name when handling Grok's output or exit code (reserved zsh variable causing execution error). Use `$?`.
- Grok can exit successfully with narration but no deliverable. Check its JSON `text` and stop reason.
- Grok 4.7 `high`/`xhigh` legs burn ~1.5–2× reasoning tokens vs 4.6 (independent benches measured ~66k output tokens per task at `high`; `xhigh` is a significant extra step at ~81k tokens). Run them backgrounded or with a generous bound (xAI's client examples use 3600s timeouts) — a tight foreground timeout kills a healthy leg.
- Grok `stopReason:"Cancelled"` with empty text = headless permission auto-cancel, not quota or concurrency (the 2026-07 "concurrent cancels" attribution showed this same signature on forensic review). Verify: `permission_resolved decision:"cancelled"` (~50 ms) in `~/.grok/sessions/…/events.jsonl`. Relaunch with `--always-approve`. This hits `--permission-mode plan` too, even on tool calls that write nothing (verified 2026-07-24 on a web-research leg) — headless runs always use `--always-approve`.
- A failed Grok run may write `{"type":"error","message":"…max_tokens_truncation…"}` with NO stopReason field — parse that schema separately from result objects. The session survives; `grok -r <sessionId> -p "continue"` resumes it (single observation, 2026-07-23).
- Grok cancel handling churned across 0.2.x (0.2.103 fixed an early-cancel session-wedge race) and the CLI is now 1.0.x — re-verify this behavior after CLI upgrades. The `--always-approve` launch shape is unchanged; 0.2.x plan-mode auto-cancel forensics were not re-run on 1.0.3.
- Grok may upload repository context. In secret-bearing repositories, keep the route disabled unless the installed CLI's upload-disable setting is verified. A warning that the configured key is unrecognized means it is not verified. Relay-routed model entries are retired (see the Grok qualifier).
- **No X tool means Grok may invent posts.** A Grok research leg with no X-search tool call cannot see X search results. A `chat_completions` entry falls back to `site:x.com` web-search summaries. A free grok.com login (CLI 1.0.41) used `web_fetch` on x.com pages, and on a keyword query it **invented three posts with placeholder IDs (`status/1234567890`)**, reported as real (verified 2026-09-27). Rules:
  - reject every post URL that did not appear in a tool result;
  - check that the model entry uses `api_backend = "responses"` with `supports_backend_search = true`, and run the X smoke test before blaming the model.
- Backgrounded `codex exec` legs can hang forever on "Reading additional input from stdin..." when the launching shell leaves stdin open. Always append `< /dev/null`, unless the prompt itself is piped on stdin with `-`. This was re-hit 6 times between 07-22 and 09-25, once as a 53-minute stall. The stdin banner on its own is not a hang: judge liveness by transcript byte growth.
- A ChatGPT-account usage limit can end a Codex leg mid-run with exit 0, no final message, and an unwritten `-o` file (2026-10-01, third Sol call of a session). Detect it by "You've hit your usage limit" in the log, not the exit code; the route is dead until the reset time the error states, and a write leg may have left a partial diff.
- Do not let an external worker perform destructive recovery or use credentials beyond the explicit task scope.
